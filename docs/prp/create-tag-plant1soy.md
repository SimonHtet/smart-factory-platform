# 🌱 Create Tag Plant 1 --- Soy Milk

System for creating **Product Date, Batch and Product ID** for the
production process **PRP1**

Supports products:

-   🌱 **Soy Milk**
-   🥛 **Fresh Milk**

The system covers everything fromcreation of **Product Date by SUP**,
creation of **Batch automatically**, data entry by Batch, selection of
**Group** through tocreation of **Product ID** before proceeding to the
next production stage

------------------------------------------------------------------------

## 📌 Overview

production process **PRP1** starts from the **Create Tag Plant 1 Soy**
where `SUP (Supervisor)` defines the data for the production run

The main data used to create Product Date includes:

  Field              Description
  ------------------ ------------------------
  **Product Date**   Production date
  **Loop**           Production loop
  **Week**           Production week
  **Start Batch**    Starting Batch number
  **Batch Count**    Number of main Batches
  **Product**        Product
  **Batch Size**     Batch size

From this data, the system creates **Product Date and Batch** in the
table `prp1_table`

> **Note:** `Group` is not assigned during Product Date creation because
> the Batch may change Group later.

------------------------------------------------------------------------

## 📅 Product Date

Product Date is created from data that `SUP` defines on the **Create Tag
Plant 1 Soy**

### Input

``` text
Product Date = 7/30/2026
Loop         = 1 Week
Week         = 31
```

The system uses the data to create `Product_Date` in the format:

``` text
300726-31Th1
```

### Product Date Format

``` text
DDMMYY-WW + Loop
```

Example:

``` text
300726-31Th1
```

Consists of:

``` text
30      = day
07      = month
26      = year
31      = Week
Th1     = Loop
```

Therefore:

``` text
300726-31Th1
```

is used as the **Product_Date** within `prp1_table`

------------------------------------------------------------------------

## 🔢 Batch

**Batch** is the production unit used to track data throughout the PRP1
process.

Batch is created together with Product Date and stored in the format **1
Batch = 1 Row**

Example:

``` text
Product_Date   Batch
300726-31Th1   125-1
300726-31Th1   125-2
300726-31Th1   126-1
300726-31Th1   126-2
```

### ✂️ Batch Split

If a main Batch must be split into two parts the system splits it into:

``` text
125-1
125-2
```

where:

``` text
125 = Main Batch
-1  = Sub-batch part 1
-2  = Sub-batch part 2
```

------------------------------------------------------------------------

## 🔢 Batch Generation

Data used to generate Batches:

  Input              Description
  ------------------ ------------------------
  **Start Batch**    Starting Batch number
  **Batch Count**    Number of main Batches
  **Product**        Product
  **Batch Size**     Batch size
  **Product Date**   Production date

### Example

Set:

``` text
Start Batch = 125
Batch Count = 2
```

The system generates the main Batches:

``` text
125
126
```

If Split Batch is enabled:

``` text
125-1
125-2
126-1
126-2
```

Therefore, the system generates a total of:

``` text
4 Rows
```

------------------------------------------------------------------------

## 🧮 Batch Count Logic

> **Batch Count MeansNumber of main Batches not the number of Rows
> generated by the system**

Example:

``` text
Start Batch = 125
Batch Count = 2
```

Means:

``` text
Main Batch 1 = 125
Main Batch 2 = 126
```

When the Batch is split:

``` text
125
 ├── 125-1
 └── 125-2

126
 ├── 126-1
 └── 126-2
```

Result:

``` text
125-1
125-2
126-1
126-2
```

Total **4 Rows**

------------------------------------------------------------------------

## 📝 Normal Batch

If a Batch does not need to be split into sub-batches, the system
creates only the main Batch

Example:

``` text
Start Batch = 125
Batch Count = 1
Split       = No
```

Result:

``` text
125
```

It will not create:

``` text
125-1
125-2
```

Therefore, the system supports both:

### Normal Batch

``` text
125
```

### Split Batch

``` text
125-1
125-2
```

------------------------------------------------------------------------

## 🏷️ Product & Batch Size

When `SUP` defines the Product and Batch Size, the system applies those
values to Batches created from the same Product Date

Example:

``` text
Product    = Soy Milk
Batch Size = 30
```

The system creates:

``` text
125-1
125-2
126-1
126-2
```

Data stored in each Row:

  Batch   Product      Batch Size
  ------- ---------- ------------
  125-1   Soy Milk             30
  125-2   Soy Milk             30
  126-1   Soy Milk             30
  126-2   Soy Milk             30

## 🆔 Product ID

**Product ID is not created yetAt the stage Create Product Date**

The system creates the Product ID when the user reaches the
**Standardized** stage and selects `Group`

### Reason

The same Batch may change Group later, so Group should not be assigned
when the Batch is initially created

------------------------------------------------------------------------

### Product ID Format

``` text
[Product Date]-[Group]
```

Example:

``` text
Product Date = 300726-31Th1
Group        = C
```

The system creates:

``` text
300726-31Th1-C
```

### Full example

``` text
Product Date = 300726-31Th1
Batch        = 125-1
Group        = C
```

Product ID:

``` text
300726-31Th1-C
```

> **Note:** `Batch` and `Product ID` are separate pieces of data
>
> -   **Batch** is used to identify the production unit
> -   **Product ID** is used to identify the product by Product Date and
>     Group

## 📊 `prp1_table` Structure

### Initial Data

While Product Date and Batch are being created, `Group` and `Product ID`
do not yet have values

  Product_Date   Batch   Product      Batch Size Group   Product ID
  -------------- ------- ---------- ------------ ------- ------------
  300726-31Th1   125-1   Soy Milk             30 \-      \-
  300726-31Th1   125-2   Soy Milk             30 \-      \-
  300726-31Th1   126-1   Soy Milk             30 \-      \-
  300726-31Th1   126-2   Soy Milk             30 \-      \-

### After selecting Group

When the user reaches Standardized and selects:

``` text
Group = C
```

The system creates the Product ID:

``` text
300726-31Th1-C
```

Example:

  ---------------------------------------------------------------------------
  Product_Date    Batch   Product       Batch Size Group   Product ID
  --------------- ------- ---------- ------------- ------- ------------------
  300726-31Th1    125-1   Soy Milk              30 C       300726-31Th1-C

  ---------------------------------------------------------------------------

## 📊 Row-Based Data Structure

The system stores Batch data using a **Row-Based Structure**

instead of creating separate Columns for each Batch

### Example

``` text
Batch 125-1 → 1 Row
Batch 125-2 → 1 Row
Batch 126-1 → 1 Row
Batch 126-2 → 1 Row
```

If there are 13 Batch:

``` text
13 Batch
   ↓
13 Rows
```

There is no need to add a new Column for each Batch

### Advantages

-   ✅ Reduces the number of Columns in the Database
-   ✅ Supports an increasing number of Batches
-   ✅ Supports Batch splitting
-   ✅ Makes data queries easier
-   ✅ Allows flexible future data expansion
-   ✅ Reduces Database Structure complexity

------------------------------------------------------------------------

## ⚙️ Automation

The system uses **Budibase Automation** to generate Batches and save
data to `prp1_table`

### Automation Name

``` text
Generate Product Batches
```

### Automation Responsibilities

1.  Receive data defined by SUP
2.  Create Product Date
3.  Generate the specified number of Batches
4.  Check whether Batch splitting is required
5.  Create a Row for each Batch
6.  Save Product Date
7.  Save Product
8.  Save Batch Size
9.  Save data to `prp1_table`

> ⚠️ This Automation **does not create Product ID yet** becauseGroup has
> not yet been assigned at this stage
